# 🧊 Glacier

Личный сервис учёта и аналитики инвестиционного портфеля. Аналог веб-части Snowball Income,
рассчитанный на себя и небольшой круг друзей: закрытая регистрация по инвайт-кодам, у каждого
пользователя полностью изолированные портфели и свои подключения к брокерам.

Работает на МосБирже (акции, облигации, фонды) и криптовалютах. Бесплатные источники котировок,
без API-ключей.

---

## Что умеет

**Учёт**
- Портфели → категории → активы → сделки и начисления
- Типы операций: покупка, продажа, дивиденд, купон, амортизация, погашение, пополнение,
  вывод, комиссия, налог, сплит
- Произвольные активы — вклады, недвижимость, всё что не торгуется на бирже
- Мультивалютность: операции в любой валюте, итоги в базовой валюте портфеля

**Расчёты**
- Позиции методом **FIFO**: комиссия покупки капитализируется в себестоимость, комиссия и
  налог продажи уменьшают реализованный результат
- **XIRR** — среднегодовая доходность с учётом переменной суммы вложений
- Прибыль с разложением на реализованную, нереализованную, полученные выплаты, комиссии, налоги
- Свободный остаток денег выводится из журнала, отдельно по валютам
- Распределение по категориям, классам активов, валютам и инструментам
- График стоимости портфеля против вложенного капитала

**Выплаты**
- Календарь дивидендов, купонов и амортизации на 12 месяцев вперёд
- Графики купонов по облигациям подтягиваются с MOEX (объявленные, подтверждённые данные)
- Для акций — прогноз по вашей же истории начислений (частота и средняя сумма)
- Forward yield к текущей цене и yield on cost к вашей себестоимости
- История полученных выплат по годам

**Ребалансировка**
- Целевые доли по категориям и текущие отклонения
- План докупок на заданную сумму — целыми лотами, жадный алгоритм минимизирует отклонение
  от целей. Только покупки: продажа ради ребалансировки создаёт налоговую базу
- Подбор что продать при частичном выводе средств

**Данные**
- Ручной ввод с поиском инструментов по MOEX и CoinGecko
- Импорт CSV — русские и английские заголовки, любой разделитель, оба формата чисел
- **Подключение нескольких брокеров** по API-ключам, каждый счёт в свой портфель

**Доступ**
- Первая регистрация создаёт администратора, дальше — только по инвайт-кодам
- Сессии в httpOnly-cookie, в базе хранится только хэш токена
- Пароли — scrypt с индивидуальной солью
- Брокерские ключи — AES-256-GCM, расшифровываются только на время запроса к брокеру

## Запуск

Требуется **Node.js 22+** (используется встроенный `node:sqlite` — нативные модули, Docker и
отдельная СУБД не нужны).

```bash
cd glacier
npm install

# Ключ шифрования (файл .env уже создан при установке; если нет — создайте)
cp .env.example .env
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
# впишите значение в GLACIER_SECRET

npm run dev
```

Откройте <http://localhost:3000>. Первая регистрация не требует инвайт-кода и создаёт
администратора — сделайте это сразу, пока сервис не доступен другим.

### Продакшен

```bash
npm run build
npm start
```

### Демо-данные

```bash
npm run seed
```

Создаёт пользователя `demo@glacier.local` / `demo12345` с портфелем из реальных бумаг MOEX,
загружает котировки и печатает рассчитанные показатели в консоль.

### Тесты

```bash
npm test
```

34 теста: XIRR (включая эталонный пример из документации Excel и случаи, где метод Ньютона
расходится), FIFO-разбор лотов, знаки денежных потоков, парсер CSV, подписи запросов к
криптобиржам (Binance — против вектора из официальной документации).

## Как подключить друзей

1. Войдите под администратором → **Админка**
2. Создайте инвайт-код, укажите комментарий и срок действия
3. Передайте код — он одноразовый
4. Друг открывает `/register`, вводит код и заводит аккаунт

Портфели, сделки, активы и брокерские подключения каждого пользователя изолированы.
Администратор видит только список пользователей и статистику, но не содержимое чужих портфелей —
каждый запрос к данным ограничен `user_id` на уровне SQL.

## Подключение брокеров

Раздел **Брокеры** в личном кабинете. Можно добавить сколько угодно ключей — у разных брокеров
и несколько ключей одного брокера (например, два аккаунта Bybit).

Модель намеренно двухуровневая:

- **Подключение** — это один API-ключ.
- **Привязка** — это пара «счёт у брокера → портфель в Glacier».

Один ключ часто видит несколько счетов (брокерский, ИИС, субсчёт). Каждый привязывается к
своему портфелю независимо, поэтому не приходится выбирать, какой из счетов вести.

### Поддерживаемые брокеры

| Брокер | Что читает | Учётные данные | История |
|---|---|---|---|
| **Т-Инвестиции** | сделки, дивиденды, купоны, комиссии, налоги, пополнения и выводы | токен T-Invest API | до 5 лет |
| **Алор** | сделки и остатки по портфелям МосБиржи | refresh-токен Alor OpenAPI | до 3 лет |
| **Bybit** | спотовые сделки и остатки единого счёта | API key + secret | до 2 лет |
| **Binance** | спотовые сделки и остатки | API key + secret | до 1 года |

Везде достаточно прав **только на чтение**. Сервис не выставляет заявки и не выводит средства —
не давайте ключу лишних прав.

### Как это работает

1. **Брокеры → Добавить подключение**, выберите брокера и заполните поля.
2. **Проверить и сохранить** — ключ проверяется у брокера и сразу сохраняется зашифрованным.
   В браузер он больше не возвращается никогда: посмотреть его нельзя, только заменить.
3. Для каждого найденного счёта выберите портфель — существующий или создайте новый.
4. **Синхронизировать**. Кнопка «Полная» перечитывает максимальную доступную историю.

Повторная синхронизация безопасна: каждая операция пишется с идентификатором брокера, а сам
идентификатор дополнительно привязан к номеру подключения — два ключа одного брокера не
столкнутся между собой, а повторный запуск не создаст дублей. Обычная синхронизация берёт
период с запасом в неделю назад от прошлой, потому что брокер может провести операцию задним
числом.

### Автосинхронизация

Чтобы не нажимать кнопку руками, есть фоновая синхронизация. Она обходит **всех пользователей**
и тянет каждый счёт, у которого включён флажок автосинхронизации на странице «Подключения» —
флажок и есть единственный переключатель.

Два способа запуска:

**1. Постоянный процесс** — уже встроен в `docker-compose.yml` как сервис `glacier-sync`,
поэтому на VPS с CI/CD не нужно делать ничего: пайплайн сам поднимает и перезапускает его
вместе с веб-приложением. Вне Docker:

```bash
npm run sync:watch   # раунд каждые GLACIER_SYNC_INTERVAL_MINUTES (по умолчанию 60)
```

**2. Внешний планировщик** — системный cron или таймер systemd дёргает эндпоинт:

```bash
# .env: GLACIER_CRON_SECRET=<случайная строка>
*/30 * * * * curl -fsS -X POST -H "Authorization: Bearer <тот же секрет>" \
  https://<хост>/api/cron/sync
```

Без `GLACIER_CRON_SECRET` эндпоинт отвечает 404 и фактически не существует. Локально один
раунд без сервера: `npm run sync:once` — код выхода 1, если хоть один счёт не синхронизировался,
поэтому cron может слать алерты.

Итог каждого раунда пишется в журнал синхронизации (виден в «Настройках»): сколько пользователей
и счетов обошёл, сколько операций добавил и по каким счетам были ошибки. Ошибка одного счёта не
останавливает остальные.

### Сертификат для Т-Инвестиций

API Т-Инвестиций отдаёт сертификат, выпущенный российским УЦ Минцифры. Его нет ни в наборе
корневых сертификатов Node.js, ни в большинстве системных хранилищ, поэтому соединение
обрывается на TLS с ошибкой `SELF_SIGNED_CERT_IN_CHAIN`.

**Ничего делать не нужно.** Связка входит в репозиторий — `certs/russian-trusted-ca-bundle.pem`,
— а `npm start` и `npm run dev` подхватывают её автоматически.

Почему это не задаётся через `.env`: `NODE_EXTRA_CA_CERTS` читается при старте процесса, а Next
загружает `.env` заметно позже, когда TLS уже настроен. Поэтому запуск идёт через
`scripts/with-ca.mjs` — он подставляет переменную и запускает Next.

В связке два сертификата, корневой и промежуточный. Промежуточный нужен потому, что сервер не
всегда присылает его сам, и без него цепочка не собирается.

Это публичные сертификаты, а не секрет. Подлинность проверяется по отпечаткам:

| Сертификат | SHA-256 | Действует до |
|---|---|---|
| Russian Trusted Root CA | `D2:6D:…:CF:31` | 27.02.2032 |
| Russian Trusted Sub CA | `BB:BD:…:FD:9B` | 06.03.2027 |

```bash
node -e "const {X509Certificate}=require('crypto'),fs=require('fs');
for (const p of fs.readFileSync('certs/russian-trusted-ca-bundle.pem','utf8').split(/(?=-----BEGIN)/).filter(x=>x.trim()))
  { const c=new X509Certificate(p); console.log(c.subject, c.fingerprint256); }"
```

Доверие ограничено процессом сервиса: в системное хранилище ничего не добавляется, на другие
программы это не влияет. Своя связка подключается переменной `GLACIER_EXTRA_CA_PATH`. Если файла
нет, при старте выводится предупреждение, а остальные брокеры продолжают работать.

Проверить состояние брокерского слоя, не имея ключей:

```bash
node --import ./scripts/register-alias.mjs scripts/check-brokers.ts
```

Скрипт показывает результат миграции схемы, список адаптеров и — главное — что именно увидит
пользователь при неверном ключе у каждого брокера.

### Алор

Токен берётся в кабинете разработчика на [alor.dev](https://alor.dev/open-api-tokens) — раздел
«Токены», достаточно доступа только на чтение.

Авторизация двухступенчатая: долгоживущий refresh-токен обменивается на JWT со сроком жизни
около 25 минут, и уже JWT подписывает запросы данных. Хранится только refresh-токен.

Список портфелей берётся из самого JWT — в его полезной нагрузке лежат коды портфелей,
доступные токену, поэтому отдельный запрос не нужен. Подпись локально не проверяется намеренно:
это наш собственный токен, доступ разграничивает сервер, а нам нужен только перечень кодов.
Рынок определяется по префиксу кода: `D…` — фондовый, `G…` — валютный, `7…` — срочный.

Одна тонкость в расчёте цены. Облигации на МосБирже котируются в процентах от номинала, акции —
в рублях. Алор в каждой сделке отдаёт поле `volume` — денежный объём, поэтому цена за единицу
выводится как `volume / количество`. Это даёт один код для обоих классов активов и совпадает с
тем, как цены хранятся во всём остальном приложении.

Как и криптобиржи, Алор отдаёт по этому эндпоинту **только сделки** — пополнения и выводы в
API не приходят, поэтому остаток свободных средств будет неполным.

### Ограничения криптобирж

Биржи отдают сделки, но не движение денег: пополнения и выводы в API не приходят. Поэтому
остаток свободных средств по такому портфелю будет неполным — при необходимости добавьте
операции «Внесение средств» вручную. Интерфейс предупреждает об этом при подключении.

У Binance есть дополнительное ограничение: список сделок нельзя запросить сразу по всем парам,
только по конкретной. Glacier подбирает пары из монет, которые лежат на счёте сейчас. Монета,
купленная и полностью проданная до подключения, не оставит остатка — её сделки не найдутся.
Bybit таких ограничений не имеет: его история читается целиком, неделя за неделей.

### Добавить своего брокера

Архитектура адаптерная: движок синхронизации не знает ни одного брокера по имени. Чтобы
добавить нового, нужен один файл в `src/lib/brokers/`, реализующий интерфейс `BrokerAdapter`:

- `credentialFields` — декларативное описание полей, форма подключения строится из него сама;
- `listAccounts` — проверка ключа и список счетов;
- `fetchOperations` — операции за период, уже в терминах журнала;
- `fetchBalances` — необязательно, текущие остатки.

Дальше адаптер добавляется в `src/lib/brokers/registry.ts`. Ни схема, ни движок, ни интерфейс
пользователя менять не нужно.

## Формат CSV

```csv
date;type;symbol;quantity;price;amount;fee;tax;currency;note
2026-01-10;deposit;;;;300000;0;0;RUB;Пополнение счёта
2026-01-15;buy;SBER;100;250,40;;25;0;RUB;Первая покупка
2026-05-20;dividend;SBER;;;3400;0;442;RUB;Дивиденд за 2025 год
```

- Заголовки распознаются на русском и английском: `дата/date`, `тип/type`, `тикер/symbol`,
  `количество/quantity`, `цена/price`, `сумма/amount`, `комиссия/fee`, `налог/tax`
- Разделитель определяется автоматически: `;`, `,` или таб
- Числа принимаются в обоих форматах: `1 234,56` и `1,234.56`
- Даты: `ГГГГ-ММ-ДД`, `ДД.ММ.ГГГГ`, `ДД/ММ/ГГГГ`
- Для сделок сумма считается сама; для начислений и движения денег её нужно указать
- Строку с колонкой `id` можно импортировать повторно — дубль не создастся
- Любая непонятая строка **показывается как замечание**, а не пропускается молча

## Оформление

Вёрстка — швейцарская типографика, палитра — снятая со светлой темы публичных
портфелей Snowball Income. Правила действуют по всему приложению:

- структуру задают волосяные линейки и воздух, а не карточки и заливки;
- ни одного скругления, тени, градиента или размытия;
- цвет несёт только данные: рост, падение, акцент. Никогда — украшение;
- цифра главная: крупная, с плотным трекингом, с табличными цифрами;
- шрифты: **Golos Text** (русский неогротеск) для интерфейса и **IBM Plex Mono**
  для тикеров и кодов.

Обе темы Snowball сняты с рендера публичного портфеля. Тёмная — по умолчанию,
переключатель в шапке; выбор хранится в `localStorage` и применяется инлайн-скриптом
до первой отрисовки, поэтому вспышки светлого фона нет.

| Роль | Тёмная (по умолчанию) | Светлая |
|---|---|---|
| Фон страницы | `#282832` | `#f9fafb` |
| Карточки | `#32323e` | `#ffffff` |
| Приглушённая / приподнятая | `#1e1e2d` / `#3f4254` | `#f3f6f9` / `#ebedf3` |
| Заголовки | `#ffffff` | `#181c32` |
| Основной текст | `#e9ecef` | `#3f4254` |
| Приглушённый / бледный | `#adb5bd` / `#7e8299` | `#7e8299` / `#b5b5c3` |
| Акцент | `#00aff5` | `#3699ff` |
| Рост | `#5cd59b` мятный | `#1bc5bd` бирюзовый |
| Падение | `#f27362` | `#f64e60` |
| Линейки | `#474b5a` | `#e4e6ef` |

Обратите внимание: у Snowball темы отличаются не только фоном — акценты и цвета
прибыли/убытка в них разные, и это перенесено как есть.

Темы переключаются переопределением переменных `--color-*` в блоке
`[data-theme="light"]`. Утилиты Tailwind v4 компилируются в `var(--color-*)`, поэтому
ни один класс в разметке дублировать не нужно. Цвета графиков — тоже `var()`-ссылки:
SVG разрешает CSS-переменные в атрибутах заливки, так что диаграммы следуют за темой
без второй палитры в JavaScript.

Распределение показано пропорциональными полосами, а не кольцевой диаграммой:
список читается за один проход и ставит название, долю и сумму на одну строку,
тогда как кольцо требует сравнивать длины дуг и отдельную легенду.

### Проверка вёрстки

```bash
npm start
node --import ./scripts/register-alias.mjs scripts/make-session.ts   # выдаст токен
node scripts/shots.mjs <токен>
```

Скрипт снимает все страницы в `shots/` через локально установленный Chrome и проверяет
каждую на нарушения правил — скругления, тени, градиенты, а заодно на горизонтальное
переполнение. Дизайн-систему легко размыть одной случайной правкой, поэтому проверка
автоматическая, а не «на глаз».

## Архитектура

```
src/
  app/
    (app)/            защищённые страницы: dashboard, assets, transactions,
                      calendar, rebalance, portfolios, connections, settings, admin
    login/ register/  вход и регистрация по инвайту
    actions/          server actions: auth, data, import, brokers
    api/search/       поиск инструментов (MOEX + CoinGecko)
  lib/
    db/               node:sqlite, схема, миграции, нормализация строк
    accounts.ts       пользователи и инвайты (без зависимости от Next)
    auth.ts           сессии, cookie, requireUser / requireAdmin
    repo.ts           доступ к данным, всегда с фильтром по user_id
    domain/
      positions.ts    FIFO, себестоимость, реализованный результат
      xirr.ts         доходность методом bracketing + бисекции
      analytics.ts    сводка портфеля, распределения, ряд стоимости
      payouts.ts      календарь выплат и прогноз по истории
      rebalance.ts    отклонения, план докупок, план продаж
    brokers/
      types.ts        интерфейс BrokerAdapter и модель данных
      http.ts         запросы к брокерам и превращение сбоев в инструкции
      registry.ts     реестр адаптеров
      engine.ts       брокеро-независимая синхронизация
      tinvest.ts bybit.ts binance.ts
    providers/        moex.ts, coingecko.ts, cbr.ts
    import/           csv.ts
    sync.ts           обновление котировок, курсов, графиков выплат
```

### Принятые решения

**Журнал операций — единственный источник правды.** Позиции, доходность и распределения
никогда не хранятся, а всегда пересчитываются. Исправили импорт — цифры сошлись сами; нет
денормализованных остатков, которые могут разъехаться с реальностью.

**Ключ и портфель — разные сущности.** `broker_connections` хранит API-ключ,
`broker_links` — привязку счёта к портфелю. Из-за того, что в первой версии это была одна
таблица, один ключ мог обслуживать только один портфель. Разделение убирает это ограничение и
позволяет исправить протухший ключ, не потеряв привязки.

**XIRR через бисекцию, а не метод Ньютона.** Ньютон расходится ровно на тех портфелях, ради
которых всё и затевалось: знакопеременные потоки, позиция закрыта и открыта заново, крупное
позднее пополнение. Здесь корень сначала локализуется сканированием сетки, затем уточняется
бисекцией — либо корректный ответ, либо честный `null`.

**Цены облигаций хранятся в деньгах.** MOEX отдаёт их в процентах от номинала. Пересчёт
делается один раз при сохранении, чтобы арифметика позиций нигде не разбирала класс актива.

**Идемпотентность импорта.** Уникальный индекс на `(portfolio_id, source, external_id)` делает
повторную загрузку отчёта или синхронизацию безопасной операцией. `source` включает номер
подключения, поэтому идентификаторы разных ключей одного брокера не пересекаются.

**Ошибка обязана быть инструкцией.** Сбой брокерского API превращается в текст с конкретным
следующим шагом. Интеграция, которая сообщает «fetch failed», непригодна для того, кто должен
её чинить.

**Прогноз всегда помечен как прогноз.** Публичный API MOEX не отдаёт дивиденды по акциям
(endpoint `/iss/securities/{secid}/dividends.json` возвращает описание бумаги без блока
дивидендов). Поэтому для акций строится прогноз по вашей истории начислений, и в интерфейсе он
всегда подписан.

**Деградация вместо падения.** Недоступный источник котировок оставляет последнюю известную
цену и отметку давности, а не ломает страницу.

## Перенос на VPS

Состояние целиком лежит в двух местах: каталог `data/` (файл SQLite) и `.env`.

```bash
# на сервере
git clone <repo> && cd glacier
npm ci && npm run build

# перенесите data/glacier.db и .env со старой машины
GLACIER_SECRET=... npm start
```

Дальше — `systemd` или `pm2` для автозапуска и nginx с TLS перед приложением. Резервная копия —
`sqlite3 data/glacier.db ".backup backup.db"`.

**Важно при переносе:** `GLACIER_SECRET` должен переехать вместе с базой. Это ключ шифрования
брокерских API-ключей — при его смене сохранённые подключения перестанут расшифровываться и их
придётся создать заново.

Котировки обновляются при открытии обзора, не чаще раза в 10 минут.
